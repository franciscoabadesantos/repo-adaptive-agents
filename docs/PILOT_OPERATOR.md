# One-team pilot operator checklist

Before inviting the team:

- install and exercise the five-minute quickstart in a clean checkout;
- seed roughly 8–15 concise, real items through normal Git review;
- verify that no item contains secrets, personal data, or restricted material by accident;
- explain the disclosure and the `useful`, `outdated`, and `incorrect` feedback commands.

During the pilot:

- invite normal repository work rather than benchmark-style tasks;
- encourage contributions, but do not pressure people to add knowledge;
- watch for an item authored by one teammate being reused by another teammate's Codex task;
- review negative feedback and correct or revoke content through Git;
- note repeated reuse and requests for additional repositories or use cases.

Keep `.team-knowledge/events.jsonl` local/private. It is a lightweight aid, not a dashboard or
performance-management record. The pilot's key observation is visible, useful cross-author
reuse—not event volume.

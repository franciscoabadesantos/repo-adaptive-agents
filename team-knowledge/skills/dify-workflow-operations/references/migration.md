# Migration

Keep a sanitized source export, app type, DSL version, and target purpose. Diff graph topology,
node types, selectors, branch conditions, and dependencies after each change. Preserve opaque
identifiers only when established by an export or current official documentation; otherwise get
a minimal target baseline.

Portable elements include topology, safe-placeholder prompts, contracts, deterministic parsing,
and fixtures. Target-bound elements include plugins, models, credentials, knowledge, access,
triggers, and publishing. List target-bound configuration as a post-import checklist instead of
claiming it transfers automatically.

Import into a controlled copy, resolve exact errors with target evidence, trace a fixture, and
publish only after acceptance cases pass. Do not promise automatic rollback, trigger/credential
transfer, or cross-version compatibility without proof.

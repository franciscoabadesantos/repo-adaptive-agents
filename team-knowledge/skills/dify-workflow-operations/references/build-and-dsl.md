# Build and DSL

State the objective, inputs, output contract, external effects, success condition, and
deterministic versus model-owned decisions. Build from a sanitized exported baseline when node
schemas, plugins, or version-sensitive DSL details matter. Verify current official
documentation and the target workspace before calling a DSL import-ready.

Change one capability at a time: graph shape, structured output, validation, then one external
integration. Confirm intended inputs reach consumers and outputs have the expected type/value;
an import alone is not semantic validation.

Before publish, verify without exposing values that the model runs, required plugins/tools are
installed and selectable, knowledge has representative retrieval, credentials are authorized
for a controlled target, and the operator can import, edit, publish, and inspect traces. Stop
and report a missing dependency rather than inventing an identifier, credential, model, or
manual workaround.
